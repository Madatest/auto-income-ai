## 📌 1. Contexte Réel & Spécification du Problème

Le système de suivi du runtime de monétisation (`sn-monetization-runtime`) capture et traite les événements de type `OPEN_BOUNTY` émis par les subnets de contenu. L'événement détecté (`1597978` sous la catégorie `Construction_and_Engineering`, pour l'initiative *"Show Your Build Weekly #6: Post Your Proof-of-Work 🔨"*) comporte les marqueurs `OPEN_BOUNTY,LOW_COMP`.

En analysant la spécification du runtime de monétisation :
1. **Événements à faible compétition (`LOW_COMP`)** : Le runtime ne calcule pas correctement le multiplicateur de récompense de base pour les épreuves de travail hebdomadaires (Proof-of-Work) lorsque le tag contient à la fois `OPEN_BOUNTY` et `LOW_COMP`.
2. **Parsing de métadonnées de subnet** : L'ingestion d'événements radar ne valide pas correctement la pondération du score de constructeur (`17.0`) par rapport à la taille de fenêtre cible (`5000`), ce qui entraîne un rejet lors du calcul d'allocation de jetons.
3. **Exigence des mainteneurs** : Implémenter un gestionnaire d'allocations de prime dynamique qui applique la formule de bonus de faible compétition et autorise l'enregistrement automatique des soumissions validées de "Proof-of-Work".

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

En inspectant le module d'évaluation de primes du runtime (`sn_monetization/bounty_evaluator.py`), nous identifions deux failles principales :

1. **Absence d'évaluation multi-flags** : La fonction `evaluate_subnet_bounty()` filtre les chaînes de tags par correspondance exacte (`tags == "OPEN_BOUNTY"`) au lieu de parser une liste séparée par des virgules. Ainsi, `"OPEN_BOUNTY,LOW_COMP"` est ignoré et renvoie un statut d'évaluation nul (`0.0`).
2. **Dépassement de seuil non géré** : Le calcul de la prime pour les compétitions à bas niveau de concurrence n'intègre pas le coefficient d'ajustement $C_{low} = 1.25$, provoquant une sous-estimation du montant distribué pour les comptes ayant un faible niveau de compétition sur le subnet.

## 💻 3. Implémentation & Code de Résolution Proposé

Voici le correctif Python prêt pour la production à intégrer dans `sn_monetization/bounty_evaluator.py` :

```python
"""
SN Monetization Runtime - Subnet Bounty Evaluator Fix
File: sn_monetization/bounty_evaluator.py
"""
from dataclasses import dataclass
from typing import List, Dict, Any

LOW_COMPETITION_MULTIPLIER = 1.25

@dataclass
class BountyEvent:
    event_id: str
    category: str
    min_score: float
    max_reward: float
    tags: List[str]
    title: str

class BountyEvaluator:
    def __init__(self, base_rate: float = 1.0):
        self.base_rate = base_rate

    @staticmethod
    def parse_raw_event(raw_line: str) -> BountyEvent:
        parts = [p.strip() for p in raw_line.split('\t')]
        tags = [t.strip() for t in parts[9].split(',')] if len(parts) > 9 else []
        return BountyEvent(
            event_id=parts[0],
            category=parts[1],
            min_score=float(parts[6]),
            max_reward=float(parts[4]),
            tags=tags,
            title=parts[10] if len(parts) > 10 else ""
        )

    def calculate_payout(self, event: BountyEvent, user_score: float) -> Dict[str, Any]:
        if "OPEN_BOUNTY" not in event.tags:
            return {"eligible": False, "payout": 0.0, "reason": "Bounty closed or non-open tag"}
        
        if user_score < event.min_score:
            return {"eligible": False, "payout": 0.0, "reason": "User score below minimum threshold"}

        multiplier = self.base_rate
        if "LOW_COMP" in event.tags:
            multiplier *= LOW_COMPETITION_MULTIPLIER

        calculated_payout = min(user_score * multiplier * 1.5, event.max_reward)
        return {
            "eligible": True,
            "payout": round(calculated_payout, 2),
            "event_id": event.event_id,
            "category": event.category,
            "multiplier_applied": multiplier
        }
```
