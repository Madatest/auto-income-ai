## 📌 1. Contexte Réel & Spécification du Problème

Dans le projet `project-a` (module `bounty-scout`), un rapport hebdomadaire automatisé signale qu'aucune opportunité n'a franchi les filtres de sélection pour la semaine du 19 octobre 2026, malgré des dizaines d'issues analysées (84 sans montant explicite, 53 hors domaine d'expertise, 35 bounty farms, 19 sous le montant minimum, 8 non-organisations, 2 < 500 étoiles).

L'analyse du système de filtrage révèle deux problèmes majeurs :
1. **Évaluation incorrecte des types** : La comparaison du nombre d'étoiles (`stars`) et des montants (`amount`) s'effectuait via des opérations lexicales de chaînes de caractères au lieu de comparaisons numériques (`"1200" < "500"` évalué à `True`), ce qui excluait à tort des dépôts éligibles.
2. **Parsing strict des montants monétaires** : Les montants formatés avec symboles (`$10`, `10 USD`, `US$10`) n'étaient pas correctement nettoyés avant filtrage, provoquant le rejet de bounties valides dans la catégorie `below minimum amount` ou `no stated amount`.

La spécification exige un moteur de filtrage robuste capables de parser correctement les montants, de transtyper les métadonnées et de produire un rapport d'exclusion exact.

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

1. **Typage faible & Mismatches Lexicographiques** : Les données ingérées depuis la réponse GraphQL/REST de GitHub ou l'API Algora arrivaient sous forme de chaînes brutes (`"stars": "1200"`). La fonction `filter_bounty()` appliquait directement `bounty.get("stars") < min_stars` sans transtypage en `int`, causant une élimination erronée des projets populaires.
2. **Parsing Regex insuffisant pour les devises** : Le filtre de montant échouait sur les représentations textuelles complexes (ex: `US$ 50.00`, `10$`) en renvoyant `None`, classant ainsi l'issue dans les bounties sans montant explicite.
3. **Absence de fallback de normalisation** : Les objets d'issues sans attributs explicites déclenchaient des exceptions non interceptées qui faisaient basculer le résultat dans le filtre par défaut.

## 💻 3. Implémentation & Code de Résolution Proposé

Voici la résolution corrective pour le module `scout/filters.py` dans `project-a` :

```python
import re
from typing import Dict, Any, Tuple, Optional

def extract_amount(amount_raw: Any) -> Optional[float]:
    """Extrait et convertit une valeur numérique depuis divers formats monétaires."""
    if amount_raw is None:
        return None
    if isinstance(amount_raw, (int, float)):
        return float(amount_raw)
    
    # Nettoyage des symboles de devises et espaces
    cleaned = re.sub(r'[^\d.]', '', str(amount_raw))
    try:
        return float(cleaned) if cleaned else None
    except ValueError:
        return None

def evaluate_bounty_filter(
    bounty: Dict[str, Any],
    min_amount: float = 10.0,
    min_stars: int = 500,
    require_org: bool = True
) -> Tuple[bool, str]:
    """
    Évalue si une issue respecte les critères de filtrage.
    Retourne (passes_filter, reason_if_filtered).
    """
    # 1. Vérification du montant
    raw_amount = bounty.get("amount") or bounty.get("bounty_amount")
    amount = extract_amount(raw_amount)
    if amount is None:
        return False, "no stated amount"
    if amount < min_amount:
        return False, "below minimum amount"

    # 2. Vérification des étoiles (Transtypage explicite)
    try:
        stars = int(bounty.get("stars", 0))
    except (ValueError, TypeError):
        stars = 0
    if stars < min_stars:
        return False, "fewer than 500 stars"

    # 3. Vérification de l'organisation
    is_org = bool(bounty.get("is_organization", False))
    if require_org and not is_org:
        return False, "not an organisation repo"

    # 4. Filtre de réputation du dépôt
    if bounty.get("is_bounty_farm", False):
        return False, "bounty-farm repository"

    return True, "passed"
```
