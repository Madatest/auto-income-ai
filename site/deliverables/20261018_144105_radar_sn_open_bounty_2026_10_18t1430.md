## 📌 1. Contexte Réel & Spécification du Problème

Le runtime d'ingestion `sn-monetization-runtime` de Relayhop capture et classe les événements de rémunération (Sats Bounties / Contests) publiés sur Stacker News (SN). Lors de la détection d'un signal radar de type `OPEN_BOUNTY` avec la signature d'événement suivante :

```text
1597420	Stacker_Stocks	2	21	10000	0	1.6	9274	28666	recent@Stacker_Stocks|top@Stacker_Stocks	OPEN_BOUNTY,LOW_COMP,FRESH	Stacker Stocks Weekly Close Contest 🟩 or 🟥- Week #15 Win up to 30k Sats!
```

Le module d'analyse radar (`RadarStreamIngestor` / `BountyFilterPipeline`) échoue ou ingère mal l'événement en raison de :
1. **Échec de validation du parsing de tags multiples** : Les indicateurs composés (`OPEN_BOUNTY,LOW_COMP,FRESH`) sont traités comme une chaîne indivisible au lieu d'un ensemble de drapeaux (flags) normalisés.
2. **Désynchronisation entre la prime d'entrée (bounty sats) et le prix total annoncé dans le titre** : Le champ de base indique `10000` Sats alors que le titre stipule `30k Sats`. Le runtime manquait de règles de cohérence pour enregistrer la valeur effective sans invalider le stream d'événements.

---

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

1. **Tag Unsplitting & Type Coercion** : Dans le module `src/radar/parser.ts`, le champ `tags` était extrait en exécutant `.trim()` sans effectuer un `.split(',')`. Par conséquent, le filtre `hasTag('OPEN_BOUNTY')` échouait ou levait une exception d'incompatibilité de type lorsque des flags additionnels comme `LOW_COMP` et `FRESH` étaient concaténés.
2. **Gestion Manquante des Primes Contest/Weekly** : L'évaluateur de récompense (`BountyEvaluator`) rejetait la ligne si le champ `bountySats` (10000) différait fortement de la détection Regex du titre (`30000` sats), au lieu d'indexer les deux métriques (`baseBountySats` et `maxPrizePoolSats`).

## 💻 3. Implémentation & Code de Résolution Proposé

Voici le correctif TypeScript concis et robuste dans `src/radar/parser.ts` pour parser correctement les données radar multipartites et calculer le rendement exact :

```typescript
// src/radar/parser.ts

export interface SNRadarItem {
  id: number;
  author: string;
  commentsCount: number;
  satsUp: number;
  bountySats: number;
  boostSats: number;
  rankScore: number;
  territory: string;
  tags: string[];
  title: string;
  maxPrizePoolSats?: number;
}

export function parseSNRadarLine(rawLine: string): SNRadarItem | null {
  if (!rawLine || typeof rawLine !== 'string') return null;
  const parts = rawLine.trim().split('\t');
  if (parts.length < 11) return null;

  const [idStr, author, commentsStr, satsUpStr, bountyStr, boostStr, rankStr, , , territory, tagsRaw, ...titleParts] = parts;
  const title = titleParts.join('\t').trim();

  const id = parseInt(idStr, 10);
  const bountySats = parseInt(bountyStr, 10) || 0;
  if (isNaN(id)) return null;

  // Split and normalize multi-tags cleanly
  const tags = tagsRaw
    ? tagsRaw.split(',').map((t) => t.trim().toUpperCase()).filter(Boolean)
    : [];

  // Parse total potential prize pool from title (e.g. "30k Sats" -> 30000)
  let maxPrizePoolSats = bountySats;
  const titlePrizeMatch = title.match(/(\d+)\s*k\s*sats/i);
  if (titlePrizeMatch) {
    maxPrizePoolSats = Math.max(bountySats, parseInt(titlePrizeMatch[1], 10) * 1000);
  }

  return {
    id,
    author,
    commentsCount: parseInt(commentsStr, 10) || 0,
    satsUp: parseInt(satsUpStr, 10) || 0,
    bountySats,
    boostSats: parseInt(boostStr, 10) || 0,
    rankScore: parseFloat(rankStr) || 0,
    territory,
    tags,
    title,
    maxPrizePoolSats,
  };
}
```
