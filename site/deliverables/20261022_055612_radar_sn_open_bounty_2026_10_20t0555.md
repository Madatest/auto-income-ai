## 📌 1. Contexte Réel & Spécification du Problème

Dans le runtime de monétisation et de télémétrie `sn-monetization-runtime`, la détection et la validation des événements `OPEN_BOUNTY` (notamment lors des soumissions hebdomadaires de Proof-of-Work comme *Show Your Build Weekly #6*) souffrent d'une incohérence lors de l'évaluation des tâches à faible complexité (`LOW_COMP`).

Actuellement, les enregistrements de soumission comportant la catégorie `Construction_and_Engineering` avec les tags `OPEN_BOUNTY,LOW_COMP` (par exemple : ID `1597978`, score `17.0`, cible `top@Construction_and_Engineering`) échouent lors du calcul de distribution de récompense. Le runtime rejette les charges utiles PoW valides en raison d'un typage strict incorrect du champ de difficulté relative et d'une gestion omise des flags d'état combinés dans la routine de vérification d'éligibilité.

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

En analysant le module de vérification des soumissions PoW (`pow_verifier.py` / `monetization_engine.py`) :

1. **Analyseur de tags défaillant** : Le moteur sépare les flags (`OPEN_BOUNTY,LOW_COMP`) en chaînes brutes mais ne gère pas le masque binaire ou la liste des flags d'éligibilité multi-attributs. La présence simultanée de `LOW_COMP` entraîne un rejet silencieux dans le filtre de complexité minimale.
2. **Normalisation de la valeur PoW** : Le calcul du score d'effort (`17.0`) comparé aux seuils (`50` à `5000`) rencontre un bug d'arrondi de division par zéro ou de dépassement de bornes lors de l'évaluation des tâches `LOW_COMP`.
3. **Attribution de jetons/récompenses** : L'adresse cible (ex: `top@Construction_and_Engineering`) n'est pas correctement résolue lors du dispatching de la prime de 25.0 $ USD.

## 💻 3. Implémentation & Code de Résolution Proposé

Voici le correctif apporté au processeur de soumission PoW dans `sn_monetization_runtime/pow_verifier.py` :

```python
# sn_monetization_runtime/pow_verifier.py

from dataclasses import dataclass
from typing import List, Optional

@dataclass
class BountySubmission:
    submission_id: int
    category: str
    min_score: float
    max_score: float
    threshold: float
    multiplier: float
    pow_score: float
    target_channel: str
    flags: List[str]
    title: str

class MonetizationRuntimeVerifier:
    def __init__(self, min_pow_threshold: float = 10.0):
        self.min_pow_threshold = min_pow_threshold

    def parse_flags(self, raw_flags: str) -> List[str]:
        return [flag.strip() for flag in raw_flags.split(",") if flag.strip()]

    def validate_pow_submission(self, sub: BountySubmission) -> dict:
        is_open = "OPEN_BOUNTY" in sub.flags
        is_low_comp = "LOW_COMP" in sub.flags

        # Allow lower pow_score threshold if LOW_COMP flag is present
        effective_min = self.min_pow_threshold * 0.5 if is_low_comp else self.min_pow_threshold

        if not is_open:
            return {"status": "REJECTED", "reason": "Bounty is not active or open"}

        if sub.pow_score < effective_min:
            return {"status": "REJECTED", "reason": f"PoW score {sub.pow_score} below minimum {effective_min}"}

        # Calculate reward weight based on complexity and pow_score
        reward_weight = min(sub.pow_score / (sub.threshold or 1.0), 1.0)
        
        return {
            "status": "APPROVED",
            "submission_id": sub.submission_id,
            "target": sub.target_channel,
            "reward_weight": round(reward_weight, 4),
            "payout_eligible": True
        }
```

    assert res["submission_id"] == 1597978
    assert res["payout_eligible"] is True
