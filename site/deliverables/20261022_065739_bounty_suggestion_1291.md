## 📌 1. Contexte Réel & Spécification du Problème

Dans la codebase SS13 de **S.P.L.U.R.T-tg** (basée sur /tg/station DM code), les zones dédiées comme le **Ghost Café** et les **Infinidorms** contiennent divers objets, équipements de chirurgie, armes spéciales (ex. épées d'énergie) et objets de jeu de rôle destinés à rester cantonnés à cet espace spécifique.

Actuellement, les joueurs peuvent transporter, tirer (pull) ou dissimuler des objets hors de ces zones dans le monde principal de la station. Bien que cela enfreigne la réglementation du serveur, il n'existe pas de garde-fou au niveau du code.

**Spécification requise :**
- Introduire une variable booléenne `ghost_cafe_only` sur `/obj` (ou `/atom/movable`).
- Lors du déplacement de l'objet (porté dans un inventaire, tiré, déplacé par traînée ou téléporté), vérifier la zone courante (`/area`).
- Si l'objet quitte les limites autorisées (`/area/ghost_cafe` ou `/area/infinidorm`), l'objet se désintègre ou est supprimé (`qdel(src)`) instantanément avec un message visuel d'avertissement.

---

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

Les objets de type `/obj` héritent de la logique de mouvement standard de `/atom/movable` dans Dream Maker (DM). Aucune vérification de périmètre géographique (`area restriction check`) n'est effectuée nativement au moment du changement de case (`turf`) ou de zone (`area`).

Lorsqu'un mob se déplace en tirant (`pulling`) ou en transportant (`contents`) un objet, l'évènement `Moved()` est déclenché sur l'objet ou sur le porteur. Sans intercepteur sur l'évènement de mouvement (`Moved()`) ou un signal `COMSIG_MOVABLE_MOVED`, l'objet peut franchir les bordures d'une zone sans restriction.

**Solution retenue :**
1. Ajouter la variable `ghost_cafe_only = FALSE` sur `/obj`.
2. Implémenter une méthode `check_ghost_cafe_bounds()` qui évalue si le `turf` / `area` actuel de l'objet possède la propriété / type Ghost Café ou Infinidorm.
3. Raccorder cette vérification au hook `Moved()` de `/obj` ainsi qu'au changement de conteneur (`on_enter_area` ou `Moved()`), garantissant une suppression propre (`qdel`) et un effet visuel si l'objet franchit la frontière.

## 💻 3. Implémentation & Code de Résolution Proposé

Voici le patch direct en langage **BYOND / DM** à intégrer dans la codebase :

```dm
// code/modules/obj/obj.dm (ou code/game/objects/objs.dm)

/obj
	/// Si VRAI, l'objet se désintègre automatiquement s'il quitte le Ghost Cafe ou les Infinidorms
	var/ghost_cafe_only = FALSE

/obj/Moved(atom/old_loc, movement_dir, forced, list/old_locs)
	. = ..()
	if(ghost_cafe_only && !check_ghost_cafe_bounds())
		vanish_ghost_cafe_item()

/obj/proc/check_ghost_cafe_bounds()
	var/turf/T = get_turf(src)
	if(!T)
		return TRUE
	var/area/A = get_area(T)
	if(!A)
		return TRUE
	// Vérification de la zone autorisée (Ghost Cafe ou Infinidorm)
	if(istype(A, /area/ghost_cafe) || istype(A, /area/infinidorm) || (A.area_flags & AREA_FLAG_GHOST_CAFE_PERMITTED))
		return TRUE
	return FALSE

/obj/proc/vanish_ghost_cafe_item()
	var/turf/T = get_turf(src)
	if(T)
		T.visible_message(span_warning("[src] se désintègre en une poussière éthérée en quittant le domaine du Ghost Café !"))
		new /obj/effect/particle_effect/sparks(T)
	qdel(src)
```
