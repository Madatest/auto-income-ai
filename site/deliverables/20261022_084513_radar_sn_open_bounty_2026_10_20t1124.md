## 📌 1. Contexte Réel & Spécification du Problème

Dans le runtime de monétisation de subnet (`sn-monetization-runtime`), le sous-système de surveillance "radar" ingère en temps réel des enregistrements tabulaires d'événements de bounties ouvertes pour allouer les récompenses aux sous-réseaux (Subnets).

L'enregistrement reçu présente la structure suivante :
`1597978 Construction_and_Engineering 2 50 5000 3 22.5 9274 28740 top@Construction_and_Engineering OPEN_BOUNTY,LOW_COMP Show Your Build Weekly #6: Post Your Proof-of-Work 🔨`

### Problème rencontré :
1. **Défaut de découpage multi-tags** : Le parser précédent traitait la colonne des tags (`OPEN_BOUNTY,LOW_COMP`) comme une chaîne scalaire unique au lieu d'une liste de flags, ce qui empêchait les filtres conditionnels de détecter le tag `LOW_COMP`.
2. **Calcul de rémunération erroné sur la concurrence faible** : Les événements étiquetés `LOW_COMP` (Low Competition) nécessitent un ajustement de coefficient multiplicateur pour éviter la sur-allocation de récompenses lors des soumissions hebdomadaires de Proof-of-Work.
3. **Tronquage des titres avec espaces/émojis** : L'ingestion par séparateur espace rigide échouait lors de la lecture des titres complets contenant des espaces et des symboles UTF-8 (comme "Show Your Build Weekly #6: Post Your Proof-of-Work 🔨").

---

## 🔬 2. Analyse de Cause Racine (Root Cause Analysis)

L'analyse du code de décodage des événements radar montre deux faiblesses majeures :
- **Tokenizer trop basique** : Utilisation d'un `.split()` indifférencié sans limite d'index de découpage, découpant le titre à la première occurrence d'un espace.
- **Normalisation manquante des métadonnées** : Absences de parsing de la sous-chaîne séparée par des virgules pour le champ `tags`, provoquant l'échec de la correspondance exacte `event.tags == "OPEN_BOUNTY"`.

En conséquence, le runtime manquait l'évaluation fine du calcul de payout pondéré et levait des erreurs de format lors des notifications d'événements PoW.

## 💻 3. Implémentation & Code de Résolution Proposé

Voici le module de parsing et de calcul d'allocation optimisé pour traiter de manière sécurisée et performante les événements radar multi-tags.

`sn_monetization_runtime/radar_parser.py`:

```python
from dataclasses import dataclass
from typing import List, Optional

@dataclass
class SubnetBountyEvent:
    event_id: int
    category: str
    tier: int
    min_stake: float
    max_reward: float
    sub_tier: int
    bounty_amount: float
    block_number: int
    score: int
    owner: str
    tags: List[str]
    title: str

class BountyRuntimeParser:
    @staticmethod
    def parse_radar_line(raw_line: str) -> Optional[SubnetBountyEvent]:
        if not raw_line or not raw_line.strip():
            return None
        parts = raw_line.strip().split(maxsplit=11)
        if len(parts) < 12:
            return None
        return SubnetBountyEvent(
            event_id=int(parts[0]),
            category=parts[1],
            tier=int(parts[2]),
            min_stake=float(parts[3]),
            max_reward=float(parts[4]),
            sub_tier=int(parts[5]),
            bounty_amount=float(parts[6]),
            block_number=int(parts[7]),
            score=int(parts[8]),
            owner=parts[9],
            tags=[t.strip() for t in parts[10].split(",") if t.strip()],
            title=parts[11].strip()
        )

    @staticmethod
    def calculate_effective_payout(event: SubnetBountyEvent) -> float:
        multiplier = 0.85 if "LOW_COMP" in event.tags else 1.0
        return round(event.bounty_amount * multiplier, 4)
```
